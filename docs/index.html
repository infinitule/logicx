An AI agent configured a finished Dolby Atmos music master in Logic Pro — 15 tracks mapped, 9 spatial objects placed, a 27-channel ADM BWF exported and chunk-verified — without taking a single screenshot or moving the cursor once. It did it by becoming a Mackie Control: a virtual MIDI device Logic adopts on its own and streams its entire mix state to.

This is not “AI mixing”. Every creative decision — placement map, levels, the final listen — is the human’s. This is about the interface between an agent and an application.

The problem, stated honestly

The default way an agent uses a desktop app is to screenshot it, find a control by pixel, click, and screenshot again. It works. It is also slow, expensive, and structurally blind — and when it fails it fails silently. Here is a real failure from this project’s logs. The agent clicked one mute button, then read the mixer back:

strip       dB   raw    pan  mute  solo
Audio 1     0.0  173.0  0    on    off      ← not asked for
Audio 2     0.0  173.0  0    on    off      ← not asked for
Audio 3     0.0  173.0  0    on    off      ← the one that was clicked
Audio 4     0.0  173.0  0    on    off      ← not asked for
...all eight strips muted...

Logic applies an edit to every selected channel strip. A screenshot taken immediately after would have shown eight lit mute buttons — and an agent that trusted its own action would have reported “muted Audio 3” and moved on.

How it works

1 · Speak an interface the app already trusts

Logic Pro has shipped Mackie Control Universal support for two decades. Faders are pitch-bend, buttons are note-on, the 8×2 character LCD arrives as SysEx, meters as channel pressure. A daemon opens a virtual CoreMIDI port pair; Logic probes it, recognises the handshake, and adopts the surface by itself. From then on Logic pushes its own state at us — names, fader positions, every LED, the playhead, the meters — and we push back faders, V-Pot turns and button presses. No focus, no window, no pixels.

2 · The app’s own display is the sensor

Nothing is reported from the command that was sent. A fader move is reported from the echo Logic sends back; a mute from the LED Logic lights; a dB value from the text Logic renders. Where a control has no absolute setter, the agent runs a closed loop until the app’s own readout agrees — or says it gave up.

3 · Documentation becomes queryable data, not memory

Apple’s four Logic Pro guides (2,686 pages) are harvested into 3,048 topic records and 7,447 parameter records — one per documented control, with its type, choices and page number. This is how the agent discovered mid-session that a second press of STOP returns the playhead to the project start: a fact it did not know and did not guess.

What we learned the hard way

SymptomThe actual cause
One mute click muted all eight stripsLogic applies mute/solo/fader edits to every selected strip. Setters now deselect first.
set value on a fader moved 0.1 dB regardless of the value sentThe slider is not absolute: set value = ±1 unit nudge, AXIncrement = ±10 units ≈ 1 dB, and the dB lives in the element’s name. Hence the closed loop.
Accessibility calls failed intermittently with “window not found”Logic exposes windows to accessibility only while frontmost, and another app stealing focus breaks a lookup between two statements.
send([0x90, 0xDF, 0x7F]) was logged as a press but Logic received RECORDAn 8-bit data byte is re-parsed by CoreMIDI into a different message, bypassing the --yes guard. Framing is now validated before anything reaches the wire.
daemon stop could have killed an unrelated processA stale pidfile containing 0 or -1 turns it into os.kill(-1, …) — every process the user owns. The pid must now verify as one of ours.
V-Pot turns edited the wrong trackIn Pan Mixer view each V-Pot is a different strip’s pan; only in Pan Channel view are they the selected strip’s object parameters. The difference is a single period in a two-character display: PN vs PN.
A modal alert blocked everything and could not be seenLogic mirrors its alert dialogs onto the MCU LCD, and a V-Pot push answers them. The blindest moment in GUI automation turned into a readable one.
Output assignment “committed” but nothing changedThe MCU preselect flashes until a V-Pot push confirms it — and the list has no “Object” entry. Object routing is unreachable from a control surface: a real ceiling, and a one-way door.
Logic sat at 100% CPU with no windows after a rebootIts configured audio interface was absent; Logic loops in MDCA::Init until the device returns. Diagnosable in seconds with sample, invisible to a screenshot.

What this is not

  • Not a general “AI controls any app” system. It works because Logic ships a documented control-surface protocol. The transferable part is the method: find the machine interface the app already exposes, and fall back to pixels only for what it genuinely cannot reach.
  • Not autonomous music-making. The placement map, the levels and the approval are the human’s.
  • Not a plug-in or a patch. Nothing is injected into Logic — a MIDI device and the macOS accessibility API, both public.
  • Not tested beyond one machine. Logic Pro 12.3.1, macOS 15, Python 3.14, one project.
  • No vendor documentation is redistributed. The harvester builds the corpus from your own copies of Apple’s PDFs.

Full method, wire format, and the step-by-step rebuild are in the repository’s docs/: METHOD.md, PROTOCOL.md, CASE-STUDY-ATMOS.md, and a generated ARCHITECTURE.md symbol index.
